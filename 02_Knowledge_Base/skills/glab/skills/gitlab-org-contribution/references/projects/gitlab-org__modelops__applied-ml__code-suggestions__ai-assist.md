# gitlab-org/modelops/applied-ml/code-suggestions/ai-assist

The AI Gateway and Duo Workflow Service (Python with Poetry, FastAPI and LangGraph). Conventional Commits are enforced on commits and on the MR title, Danger fails MRs of 1000 changed lines or more, and the unit and arm64 jobs need runners forks do not have. gitlab-bot closed more community MRs here than any other cause, after weeks of nudges about failing pipelines or open feedback.

| Fact | Value |
| --- | --- |
| Default branch | `main` |
| Language | Python |
| Fork to use | Community fork `gitlab-community/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist` |
| Merge settings | Squash default on, merge trains on |
| Commit convention | Conventional Commits through commitlint (`config-conventional`, header at most 100 characters), in a lefthook pre-push hook and the CI job `lint:commit`, which also lints the MR title |
| MR template | `Default.md`: what and why, numbered validation steps, checklist (tests, docs, the SWE-bench sanity check trigger, executor compatibility), and commented `/label` lines |
| Changelog | None to edit; semantic-release publishes versions and comments the version on merged MRs |
| Contributor docs | `CONTRIBUTING.md`, `AGENTS.md`, `docs/` |

Each rule ends with its kind and its sources (see the legend in `INDEX.md`).

## Rules

- Give the MR a Conventional Commits title of at most 100 characters and mark it ready instead of keeping `Draft:` in the title: `lint:commit` runs commitlint on the title as well as the commits, and a `Draft:` title fails it. (enforced; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:AGENTS.md@64953fa8`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:commitlint.config.js@309d16af`)
- Keep the diff under 500 changed lines where you can and split anything near 1000: Danger warns at 500 and fails at 1000 unless a member adds `~pipeline::skip-large-diff`. (enforced; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:danger/large_diff/Dangerfile@0dfa7bf3`, [!6472](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6472), [!6888](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6888))
- Pick exactly one `type::` label from the commented `/label` lines in the template and add the owning group's `group::` label (for example `group::ai core infra`): the template applies no label itself, its only active quick action being `/assign me`. As a non-member, set both with `@gitlab-bot label`, since quick actions do nothing without a role. (documented; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:AGENTS.md@64953fa8`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:.gitlab/merge_request_templates/Default.md@363657b3`, [!7282](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/7282))
- Run `make lint`, `make format` and the lefthook pre-commit hooks (mypy, ruff, pylint, codespell, docformatter, editorconfig, and Vale plus markdownlint on Markdown) before pushing, and `CI=true make check-mypy` for your change. Do not add an inline pylint or mypy disable without a comment giving the reason. (documented; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:CONTRIBUTING.md@f806c7a6`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:lefthook.yml@e1c1b40c`)
- `.tool-versions` pins Python 3.12.15 and Poetry 2.4.1 (the CI default image is `python:3.12.15`), and also Node 24.21.0 for markdownlint-cli2, Go 1.24.6, buf 1.71.0, gcloud, Vale, lychee and lefthook; install them with `mise install`. `AGENTS.md` says to run the `make` targets rather than the tools directly, because the doc linters come from `.tool-versions` through mise, not npm ("`npx markdownlint-cli2` fails even though `make markdownlint` works"); to run specific tests use `poetry run pytest <path>`, since `make test` takes no path. CI's `lint:doc` runs `make lint-doc` in the docs-gitlab-com lint image that `DOCS_LINT_IMAGE` names. (documented; enforced; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:.tool-versions@b07d67f6`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:.gitlab-ci.yml@9b455b23`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:.gitlab/ci/lint.gitlab-ci.yml@4e19f61e`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:AGENTS.md@64953fa8`, `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:README.md@6c8dc9ad`)
- After changing `contract/contract.proto` (resolving a merge conflict in it included), regenerate the clients with the `gen-proto-*` targets instead of editing them: the `check-proto-*` jobs fail on any byte difference. Give each changed client a version higher than the one on `origin/main`: `gen-proto-node` bumps `clients/node/package.json` only when its output changes in that run, so compare it yourself, and bump the Ruby client's `version.rb` and `Gemfile.lock` by hand. Check both again after merging `main`. (enforced; `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:AGENTS.md@64953fa8`)
- Expect unit and build jobs that need large or arm64 runners to fail on a fork with `no_matching_runner`, and personal forks to run out of CI minutes. Once the jobs your fork can run are green, ask a member to trigger the pipeline in the parent project; then read its logs, because failures there are yours to fix. (observed, 8 MRs; [!6275](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6275), [!6469](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6469), [!7144](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/7144), [!7175](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/7175))
- Target `main`, not a stable release branch; fixes reach release branches from `main`. (observed, 1 MR; [!5984](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/5984))
- Expect one reviewer and then one maintainer; Danger's roulette suggests domain reviewers. When several assigned reviewers decline the area, name a reviewer from the roulette or the history of the files you touched rather than waiting. (observed, 2 MRs; [!6387](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6387), [!6393](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6393))
- Check that the tool or feature you change is not deprecated and that the design was not already decided elsewhere; fixes to a deprecated tool, an alias for a tool no workflow uses and a negotiation decided against in another discussion were declined. (observed, 3 MRs; [!7193](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/7193), [!6388](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6388), [!6392](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6392))

## Troubleshooting

**`lint:commit` fails on a title starting with `Draft:`**
- Cause: commitlint lints the MR title as well as the commits, and `Draft:` is not a Conventional Commits type.
- Fix: mark the MR ready (or rewrite the title) and run a new pipeline.
- Who can fix it: you.
- Sources: `gitlab-org/modelops/applied-ml/code-suggestions/ai-assist:AGENTS.md@64953fa8`

**Jobs fail with `no_matching_runner` or `ci_quota_exceeded` on your fork**
- Cause: the jobs need large or arm64 runner tags, or your personal namespace has no CI minutes left.
- Fix: use the community fork, and ask a member to trigger the pipeline in the parent project.
- Who can fix it: a maintainer or member.
- Sources: [!6469](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/6469), [!7175](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/merge_requests/7175)
