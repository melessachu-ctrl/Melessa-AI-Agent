## gitlab-org/theseus/theseus

A Hugo documentation site for the Theseus initiative. Every community-labeled MR in the corpus came from a branch in the project by someone with access, so nothing is known about how outside contributions are handled.

- Facts: default branch `main`; no community fork; squash default off, pipeline must succeed, threads must be resolved; no commit lint (merged titles use `docs:` or `feat(site):`); template `Default.md` (what and why, references, `initiative::theseus` label); no changelog.
- Use the `Default.md` template, and build the site locally with Hugo extended installed through mise after initializing the theme submodule; the `build-docs` job builds the site on MR changes. Lint Markdown with `rumdl check docs` (pinned in `mise.toml`), and fix an absolute-link finding by making the link relative rather than disabling the rule. (documented; `gitlab-org/theseus/theseus:AGENTS.md@843e5b13`, `gitlab-org/theseus/theseus:.gitlab/merge_request_templates/Default.md@206ae19d`)
- Troubleshooting: nothing project-specific is known, since no outside MR appeared. With no community fork, a personal-fork pipeline runs on your own CI minutes; if `build-docs` fails, build the site locally as above (the theme submodule is the usual missing piece) before asking for help. Who can fix it: you. (documented; `gitlab-org/theseus/theseus:AGENTS.md@843e5b13`)

## gitlab-org/ruby/gems/labkit-ruby

LabKit for Ruby, the gem GitLab's Ruby services use for logging, tracing, metrics and correlation. semantic-release versions it from commit types.

- Facts: default branch `master`; community fork `gitlab-community/gitlab-org/ruby/gems/labkit-ruby`, created on 2026-10-19; squash default off, merge trains on, pipeline must succeed, threads must be resolved; template `default.md`; changelog generated by semantic-release, never edited by hand; Danger runs the roulette with the changelog and commit message rules disabled.
- Write Conventional Commits with a module scope (`fix(rate_limit): ...`) and choose the type for the release it should cause: `feat` a minor, `fix`, `perf` and `revert` a patch, `!` or a `BREAKING CHANGE` footer a major, other types none. (documented; `gitlab-org/ruby/gems/labkit-ruby:AGENTS.md@d8c15f27`)
- Run `bundle exec rake verify` (RSpec and RuboCop, what CI runs) before pushing and `bundle exec rake fix` to autocorrect; some specs need Redis; do not edit `.rubocop_todo.yml`; keep public APIs backward compatible (new keyword arguments get defaults); one concern per MR. (documented; `gitlab-org/ruby/gems/labkit-ruby:AGENTS.md@d8c15f27`, [!358](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/358))
- The specs that need Redis connect to `LABKIT_TEST_REDIS_URL`, default `redis://localhost:6390/0`; when nothing answers there and neither `CI` nor that variable is set, the spec helper runs `docker compose up -d redis` (or `docker-compose`) from the repository and stops it at exit. Without Docker, start a Redis yourself and set `LABKIT_TEST_REDIS_URL`; CI uses a `redis:8-alpine` service. `.tool-versions` pins Ruby 4.0.7, and CI also runs the specs on 3.4 and 3.3. (enforced; `gitlab-org/ruby/gems/labkit-ruby:spec/support/test_redis.rb@3d256250`, `gitlab-org/ruby/gems/labkit-ruby:.gitlab-ci.yml@b7e9010d`, `gitlab-org/ruby/gems/labkit-ruby:.tool-versions@ef29ad0b`)
- Troubleshooting: a fork pipeline cannot go green because the protected-runner jobs and the downstream conformance-spec pipeline need the canonical project, and the project only merges green pipelines. danger-review reads its token from Vault, which the fork cannot reach, so it fails there ("Danger cannot run without API access"); since [!388](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/388) (merged 2026-10-20) it is `allow_failure` for MRs from the community fork and no longer blocks the pipeline. Run `bundle exec rake verify` locally and ask a maintainer to run the pipeline; they may port your unchanged commit into a canonical MR and close yours in favor of it, which is not a rejection. Who can fix it: a maintainer. (enforced; observed, 4 MRs; `gitlab-org/ruby/gems/labkit-ruby:.gitlab-ci.yml@b7e9010d`, [!358](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/358), [!380](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/380), [!381](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/381), [!382](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/382))
- Why MRs were closed: all four closed community MRs were ported into the canonical project with the authors' commits so the protected jobs could run ([!358](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/358), [!380](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/380), [!381](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/381), [!382](https://gitlab.com/gitlab-org/ruby/gems/labkit-ruby/-/merge_requests/382)).

## gitlab-org/fleeting/fleeting

Fleeting, the Go library and gRPC plugin protocol behind GitLab Runner's instance and docker-autoscaler executors, with the SSH and WinRM connector and an exported integration test harness that plugin repositories run.

- Facts: default branch `main`; community fork `gitlab-community/gitlab-org/fleeting/fleeting` (pipelines go green there); squash default off but chosen per MR (MRs with the box ticked landed as one commit), merge commits, pipeline must succeed, no merge train; no `CONTRIBUTING.md`, MR or issue template, Dangerfile, `AGENTS.md` or `.gitlab/duo` instructions; `CODEOWNERS` assigns everything to the runner maintainers group; `DESIGN.md` must match `provider/interface.go`; no commit message convention (plain and Conventional subjects both merged), no `Changelog:` trailer, no sign-off or signing checked; MIT license. (checked 2026-10-21; `gitlab-org/fleeting/fleeting:LICENSE@3ac2e911`, [!151](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/151), [!143](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/143))
- CI runs only in merge request pipelines and has two jobs, `test` (golang) and `test-fips` (a UBI Go image with `GOEXPERIMENT=boringcrypto`, `-tags=fips` and CGO), both running `make test`. There is no lint job, so run `make lint` yourself; it uses the golangci-lint version pinned in the Makefile. `make test` downloads protoc (it needs `unzip` and network access), regenerates the protobuf code and the connector mocks, and fails when `go.mod`, `go.sum` or `internal/plugin/proto` change. Its mock check diffs `./mocks`, but mockery writes to `./connector/mocks`, so CI does not catch stale mocks: after changing the connector `Client` interface, run `make mock` and commit `connector/mocks/Client.go`. (enforced; `gitlab-org/fleeting/fleeting:.gitlab-ci.yml@edaacb0b`, `gitlab-org/fleeting/fleeting:Makefile@7466fae0`)
- After changing the protobuf definitions run `make compile_proto` and commit the generated files. Add new protobuf fields at the end with new numbers, never renumber, and make a new RPC optional by treating `codes.Unimplemented` from an old plugin as a no-op. (observed, 2 MRs; [!51](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/51), [!54](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/54))
- Squash is decided per MR: the default is off, and MRs merged with the box ticked landed as one commit while others kept every commit. When yours will land as written, make each commit a reviewable step and fold web-editor "Update file" or fix-up commits before review; keep the exported integration test API (`TestProvisioning`, `Config`) stable. (enforced; observed, 6 MRs; [!48](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/48), [!51](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/51), [!53](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/53), [!54](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/54), [!148](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/148), [!150](https://gitlab.com/gitlab-org/fleeting/fleeting/-/merge_requests/150))
