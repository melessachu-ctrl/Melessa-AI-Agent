# 設計原則（Ricky Design Guideline）

HKTVmall App 的設計取捨準則（王語錄 · 設計篇 · 第二修訂版精要），共 9 條，編號 R1–R9。所有設計出稿、Prototype 和設計評審都要遵守。通用的 UX 和無障礙規範之外，這 9 條是 HKTVmall 專屬的決策依據；兩者有衝突時，以本頁為準。

> 一句話：以顧客意圖與分群為準，多數用戶與 core flow 優先；在可讀的前提下提高資訊密度和模組清晰度；改版不動位置與圖示，不藏選擇，文案極短而 CTA 結果明確；無銷售價值的 T&C 不當眼；大改與下線以數據為準，優先保護五年老用戶的操作記憶。

## R1 以顧客意圖為中心

- **先釐清第一意圖。** 每頁先釐清顧客的第一意圖，一頁可以有多個。
- **分清進入方式。** 區分主動進入和被導流進入。被導流進入的顧客，要用機制喚起並放大需求。
- **分清必備資訊和雜訊。** 必備資訊是不可漏、不可誤解的內容；雜訊是多餘的圖形和編排。必備不等於當眼：必備只要求可發現、可理解，不要求一律放在主視線。
- **用行為訊號優化。** 例如同一個搜尋，背後可能有不同目的。
- **多數優先，保護 core flow。** 少數用戶或罕見情境不可拖慢、複雜化或擠佔主流程，要用次路徑或進階入口處理。
- **T&C 和免責聲明：**
  - 沒有銷售價值的，不當眼，只放在 T&C popup。
  - 有銷售價值的，即能減低疑慮、促成結帳的，可以當眼。例如把膠袋費標示為「政府徵費」，讓顧客明白這不是 HKTVmall 的額外收費。

## R2 改版保守：位置與辨識不變

新舊設計對照時，UI 元素、圖示和位置原則上不變，以降低重新學習的成本。

## R3 選擇可見：不隱藏關鍵訊息

如果「有這麼多選擇」本身就是核心訊息，就不要收合選項。例如品類模組和品牌模組要保持可見、可掃。本條不適用於 T&C 和免責聲明（見 R1）。

## R4 文案極短：結果明確

- 全新的 UI 控件要有文字說明，但不超過半句。
- 介面說明和教學一律精簡，因為多數人不會細讀，寫得太長等於沒寫。
- Button 和 CTA 的文字要說明按下後得到什麼，同時保持極短。
  - 避免：只寫「確認」「提交」而沒有結果語境。
  - 避免：為求完整而寫成長句。

## R5 一屏盡覽：資訊密度優先

在不嚴重影響可讀性、不分散對重點的注意力的前提下，每屏盡量承載更多資訊和功能區塊，讓顧客一眼掌握我們提供的內容和能力。首頁尤其如此。

## R6 模組邊界清楚

每個區塊或模組要用線框或強烈的顏色對比分隔，讓所有顧客都看得出哪些元素屬於同一組。

## R7 下線與大改：用數據把關

棄用或大幅改動功能前，要有現有使用數據評估影響。經驗法則：超過 5% 顧客使用的功能，不可動。

## R8 尊重五年老用戶的肌肉記憶

大量營收來自使用同一套 UI/UX 超過五年的忠誠顧客，任何變更都要盡量減少干擾他們的操作記憶。例外情況是數據或回饋顯示現有流程已是長期痛點，即顧客長期在抱怨，而不只是習慣了而已。

## R9 分群思考影響：忠誠客、輕度客、新客

評估影響時，要分開考慮忠誠客、輕度客和新客。三者在需求、對商品的認知、使用習慣和商業價值上都不同。

## 與本 Design System 的對應

下表是本 Design System 對各原則的建議做法，並非原文規定。

| 原則 | 在本 Design System 的做法 |
| --- | --- |
| R1 必備與雜訊 | 必備資訊用 `text-primary` 或 `text-secondary`。`text-tertiary`（白底 3.4:1）只用於非必要資訊。T&C 內文在 popup 內用 `body-3-regular` 配 `text-secondary`。 |
| R4 文案極短 | 新控件的說明用一行 `body-3-regular` 或 `caption-1-regular`；Button 文字用 `title-semibold` 或 `body-2-semibold`。 |
| R5 資訊密度 | 列表優先用 `body-2` 和 `body-3` 這兩級，多欄列表的價錢用 `price-listing-multi-col`。間距以 `spacing-8` 和 `spacing-12` 為主，不要動輒用 `spacing-24` 或以上。 |
| R6 模組邊界 | 模組之間用底色對比：`background-grey-50` 作頁面底，模組用 `background-white`，圓角用 `radius-card-s` 或 `radius-module`。需要線框時用 `stroke-secondary` 配 `stroke-width-regular`。 |
| R2、R8 位置不變 | 改版時沿用現有的 token 和 icon。換色或換字級屬於「改動」，要在交付文件中列明。 |

## 評審清單（Ricky Pass）

設計出稿或評審時逐項勾選。違反 R2、R7、R8 的項目預設為 Must fix，除非有數據證明是長期痛點。Findings 用 `ricky:R{n}` 標註對應的規則。

- [ ] **R1** 已釐清第一意圖；已分開主動進入和被導流進入；已剔除雜訊；core flow 沒有為少數情境犧牲；無銷售價值的 T&C 只放 popup
- [ ] **R2** 改版的元素位置和圖示與舊版一致，或已說明必須改動的理由
- [ ] **R3** 選擇豐富度是核心訊息時，沒有收合選項
- [ ] **R4** 新控件的說明不超過半句；Button 和 CTA 結果明確而不冗長
- [ ] **R5** 資訊密度充足，首屏可一覽，可讀性沒有受損
- [ ] **R6** 各模組有明確邊界（線框或強烈對比）
- [ ] **R7** 棄用或大改的功能已查使用數據；超過 5% 用戶使用的功能沒有改動
- [ ] **R8** 對五年老用戶肌肉記憶的影響已減至最小
- [ ] **R9** 已分別評估對忠誠客、輕度客、新客的影響
